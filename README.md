# 300k Timer

一个原生 macOS 状态栏计时器。

- 点击菜单栏沙漏打开面板；开始、暂停或继续本次专注。本次计时没有手动重置，睡一晚醒来后自动清零（见下方「睡眠检测」）。
- 默认键盘、鼠标 **5 分钟没有活动** 后暂停。阈值可选 5 / 10 / 15 分钟，也可关闭。达到阈值时扣回从最后一次键鼠操作起的闲置时间；回来操作后自动继续。
- 锁屏、休眠、切换用户时暂停。闲置暂停会唤出面板显示原因，鼠标一动或按键即继续计时并自动收起面板（Chrome 在前台时会先即时检查当前页，分心网站不恢复）。浏览分心网站触发的暂停只弹出 1 秒提示后自动收起，不需要点击。
- 面板仅显示本次计时、开始/暂停的纯图标按钮，以及今日累计。
- 设置内可查看历史总时长和按日期倒序排列的每日记录，历史数据继续保存在本机。
- 菜单栏只显示系统沙漏图标。未开始时采用系统默认单色（暗色菜单栏为白色）；运行时为绿色、下半填充；暂停时为橙色。图标按 19 pt 中等字重配置，无持续动画。
- 使用原生 macOS 菜单半透明材质、细边缘和系统窗口阴影，跟随系统深浅色模式；减少透明度开启时切换为实色背景。

## 构建与运行

需要 macOS 14+ 和 Swift 6 工具链（Command Line Tools 或 Xcode）。不依赖第三方库。

```sh
./scripts/build.sh
open "dist/300k Timer.app" --args --show-panel
```

默认构建 release。可使用 `CONFIGURATION=debug ./scripts/build.sh` 进行开发构建。

签名：首次运行 `./scripts/make-signing-identity.sh` 生成本机自签证书（存放在已忽略的 `.signing/` 专用钥匙串，不改登录钥匙串和系统信任设置）。之后每次构建签名身份不变，系统会保留「自动化 → Chrome」授权。没有该证书时退回 ad-hoc 签名；也可用 `SIGNING_IDENTITY` 指定其他证书。

核心逻辑检查（无需 XCTest，也能在只有 Command Line Tools 的机器上运行）：

```sh
swift run TimerCoreChecks
```

## 结构

- `Sources/TimerApp`：状态栏、面板、闲置检测和本地记录。

- `Sources/TimerCore`：可测试的计时状态、跨日期累计、睡眠检测，以及网站规则表 `SiteCatalog`（同一张表决定是否暂停学习、是否计入垃圾时间）。
- `Resources`：应用信息。
- `scripts/build.sh`：编译、打包和签名。
- `Tests/TimerCoreTests`：无需测试框架的核心回归检查。

个人记录在 `~/Library/Application Support/300k Timer/focus-state.json`。每 10 秒以及开始、暂停、退出时原子保存；意外终止最多可能丢失最近 10 秒。退出前正在计时，或因闲置、锁屏、休眠暂停时，重新打开后遇到近期键鼠活动会继续；关闭期间不补算。手动暂停、保持暂停和网站触发暂停不会自动恢复。数据解码失败时不会覆盖原文件；写入失败会在面板提示，并在下次保存时重试。

## 本机验证（2026-09-08）

- 已安装到 `~/Applications/300k Timer.app`，确认原生面板启动、开始和暂停累计、自动闲置提醒、设置内容及初始归零状态。
- 核心检查通过（当前 19 项）：计时状态切换、跨午夜分配、休眠/时钟异常间隔、恢复与重复暂停、旧版设置迁移、闲置阈值、会话状态、跨小时统计与持久化。

应用图标是透明底的绿色系统沙漏，浅色与深色背景共用同一图形，不含文字或底板。

面板为 260 pt 紧凑宽度；macOS 26 使用 AppKit NSGlassEffectView 的 regular 材质直接承载内容，旧系统使用 NSVisualEffectView 的 popover 材质；不降低材质透明度，不叠加 SwiftUI 背景。


闲置检测综合硬件与会话事件源、鼠标和滚动事件；无需切换标签页，也不读取输入内容。

设置页提供按日期切换的 24 小时学习柱状图，悬停可查看每小时累计。时段统计与每日总量保存在同一份本地 JSON 中，沿用每 10 秒及状态变化时的原子保存。旧记录没有时段明细的部分保留总量，不填造分布。

Chrome 在前台时，每 2 秒检测当前标签页：B 站及短链、小红书及短链、Leaguepedia（lol.fandom.com / lol.gamepedia.com / leaguepedia.com）、贴吧会自动暂停。后台标签页不触发；网址只在内存匹配，不保存。首次检测需允许系统自动化授权；权限或读取失败会在面板显示提示。

## 耗电与进程开销测试

```sh
python3 scripts/energy-test.py --duration 300 --interval 5 --label paused
```

脚本不改变计时状态，`--label` 仅用于标注场景。分别手动设置暂停、计时且 Chrome 不在前台、计时且 Chrome 前台普通网页，重复采样可比较监听开销。输出在忽略的 `dist/energy-tests/<时间>/`：原始 top、CSV、整机电池状态、JSON 汇总和 Markdown 报告。

首帧 top 数据被剔除；进程退出或采样不完整时不生成成功报告。CPU、内存、IDLEW 和 POWER 分值用于定位开销，POWER 不是瓦数，也不能折算为本 App 的电池耗电量。实际续航比较需在电池供电、相同亮度及后台负载下做更长时间的对照。

## 学习日与自动恢复

- 学习日为本地时间 01:00 至次日 01:00。凌晨零点到一点归前一天。本次计时不随 01:00 归零，而是在检测到睡眠后清零。
- 每日记录、今日累计、时段图统一按这个边界展示。底层日历日和小时明细继续原样保存，已有总时长不变；没有小时明细的旧记录不猜测归属。
- 闲置/锁屏/休眠后恢复需要新的键鼠活动；等待期间每 2 秒检查输入计数，鼠标活动也可直接触发。Chrome 在前台时先检查当前页，命中分心网站或检测失败不会自动恢复。
- 回归检查覆盖 01:00 分界、跨边界闲置回退、退出/重启意图持久化、旧记录归零、手动/网站暂停，以及活动恢复条件。

## 睡眠检测

- 连续 4 小时以上没有键鼠操作，且其中至少 1 小时落在本地 00:00–08:00，视为一次睡眠；傍晚、下午的长时间离开不算。App 关闭期间同样判断（依据保存的最近操作时间，精度约 1 分钟）。
- 醒来后的第一次操作时：本次计时清零、回到「未开始」，取消锁屏/休眠后的自动恢复，不会自动开始计时。今日累计、每日记录不受影响。
- 设置页显示最近一次睡眠的起止时间和时长。
- 兜底：没有操作历史的旧记录，或连续两个学习日都未检测到睡眠时，仍在 01:00 学习日边界清零。

## 垃圾时间

独立页签显示今日垃圾时间、与今日学习的占比、按站点排序的明细和近 7 天柱状图；统计 Chrome 前台当前标签页中的 B 站、贴吧、斗鱼、小红书、X（包含 twitter.com）。每 2 秒采样，只有连续确认同一网站的区间才计入；切换与检测失败可能少计一个采样间隔，后台标签不计时。它独立于学习计时，无新增弹窗。固定 5 分钟无键鼠活动时扣回闲置区间，活动恢复后继续；锁屏、休眠和退出期间不累计。

按凌晨 1 点分日，保存各日各站点秒数在原有 JSON 的可选 wasteTime 字段中。旧学习记录兼容，原有学习暂停网站规则不变。只保存聚合时长，不存网址和标题。退出前不足 5 分钟的无操作区间仍按当时累计保存，重开后不追记关闭期间。
